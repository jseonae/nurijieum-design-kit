누리지음(nurijieum) — eGovFramework 5.0 호환성확인 레벨 2 제출 문서

기준일: 2026-06-16

이 폴더는 누리지음(nurijieum) CMS 플랫폼의 eGovFramework 5.0 호환성확인 레벨 2 제출 문서 정본 세트다. 구버전 docs/egov-compatibility-*.md, docs/egovframework-compatibility-level2-feasibility.md, docs/cert-readiness-egov5-wa.md는 옛 프로젝트명(cmsmsa_v2)·좁은 제출 범위 기준의 deprecated 문서이며, 이 폴더(docs/cert-egov5/)가 최신 정본이다.

한 줄 결론

누리지음은 eGovFramework 5.0 기반의 범용 공공기관 CMS 플랫폼이며, 호환성확인 레벨 2의 핵심인 MVC·서비스·데이터액세스 아키텍처 규칙을 ArchUnit 테스트로 강제하고 있다. 신청 범위는 구현 완료된 platform 10개 서비스와 이를 받치는 core 모듈 전체다.

제품명과 기술 식별자

  • 산문상의 제품/프로젝트명: 누리지음(nurijieum)
  • Maven 아티팩트 ID: cmsmsa-v2 (root), 버전 1.1.0
  • Java 패키지 루트: kr.cmsmsa.v2

산문에서는 제품명을 "누리지음"으로 쓰되, 빌드 산출물·패키지·파일 경로는 저장소 실제값(cmsmsa-v2, kr.cmsmsa.v2)을 그대로 인용한다. 이는 증빙 정합성을 위한 것으로, 두 이름은 같은 산출물을 가리킨다.

AI 미포함 선언

누리지음은 AI 미포함 CMS 플랫폼이다. production 코드에 LLM/AI 의존성(spring-ai, anthropic, openai, langchain 등)이 없으며, ChatClient/VectorStore 류 심볼도 없다. 이 제출 문서는 순수 CMS 기능(site, domain, route, menu, page, content, version, publish, board, media, code, identity/permission, member, audit)만을 대상으로 한다.

  • 표준프레임워크 호환성확인 마이크로사이트: https://open.egovframe.org/oc/compatibility.do

공식 표현상 본 절차는 "인증"이 아니라 "호환성확인"이며, 레벨 2는 실행환경을 변경 없이 사용하는 것을 넘어 표준 아키텍처(MVC·서비스·데이터액세스)대로 실제 구현했음을 요구한다.

공식 제출 절차와 본 문서의 위치

호환성확인은 유료·외부 점검 서비스다. 절차는 다음과 같다.

  1. 호환성확인 신청서(점검기관 양식)에 업체·솔루션 정보를 기재해 신청.
  2. 사전미팅에서 솔루션 소개·구조 확인(본 문서 세트가 이 단계의 자료다).
  3. 계약·비용 정산 후 점검기관이 수행과제를 제공.
  4. 업체가 호환성 가이드를 준수하며 과제 수행.
  5. 원격/방문 점검: 과제 산출물·솔루션 소스·화면 CRUD 동작 확인.
  6. 호환성 확인서 발급(평균 3~4주).

본 문서 세트의 위치: 위 2·4·5단계를 뒷받침하는 솔루션 소개·구조·증빙·재현 자료다. 다음은 본 세트에 포함되지 않으며 별도로 준비해야 한다.

  • 공식 신청서(점검기관 제공 양식) — 임의 작성 불가.
  • 라이브 CRUD 점검과 솔루션 소스 확인 — 점검 당일 실연으로 이뤄지며 문서로 대체되지 않는다.

06/07의 증빙 수치는 2026-06-17 MariaDB .18(10.5.29)에서 실제 실행해 채웠다(dependency:tree, submission scope mvn test 883/0/0/26, 7개 서비스 통합·schema·core 체인 전부 통과). MySQL 8.4 secondary 호환 검증만 Docker 미가용으로 후속 과제로 남는다.

eGovFramework 5.0 호환성확인 레벨 2 적격성 판단

기준일: 2026-06-16 · 대상: 누리지음(nurijieum) — eGovFramework 5.0 기반 공공기관 CMS 플랫폼

0. 결론

항목 판단
레벨 2 달성 현실성 높음(High). 핵심 아키텍처 규칙(MVC·서비스·데이터액세스)을 ArchUnit으로 전 서비스에 강제하고 있다.
핵심 강점 RTE 5.0 필수 4종 적용, EgovAbstractServiceImpl 간접 확장, mapper 인터페이스 @EgovMapper + 표준프레임워크 제공 MapperConfigurer 등록을 ArchUnit으로 자동 검증한다.
남은 작업 증빙 산출물(dependency tree, test/통합 결과)을 현행 트리에서 재실행해 수치를 확정하고, 빈 골격 모듈을 명시적으로 제외한다.
목표 표현 공식 표현상 "인증"이 아니라 "호환성확인"으로 관리한다.

레벨 2의 핵심은 eGov dependency가 존재한다는 사실이 아니라, MVC-Service-DataAccess 계층과 실행환경 설정을 공식 규칙대로 사용하고 관련 기능이 정상 동작함을 증빙하는 것이다.

1. 레벨 개념 (호환성 가이드 2024-11-14 기준)

호환성확인은 7개 규칙 준수 여부로 레벨을 산정한다.

  • 레벨 1 = 실행환경(라이브러리·설정) 활용 및 변경금지 중심의 기본 호환(규칙 1·2·6).
  • 레벨 2 = 레벨 1 + 아키텍처 규칙 전면 준수(규칙 3 MVC / 4 서비스 / 5 데이터액세스 / 7 전체 적용). 실행환경을 변경 없이 쓰는 것을 넘어 표준 아키텍처대로 실제 구현했음을 요구한다.

누리지음은 아키텍처 규칙(3·4·5·6)을 ArchUnit 테스트로 강제하므로 설계 단계부터 레벨 2를 의식한 구조다.

2. 공식 7규칙 충족 요약

# 규칙 요지 누리지음 현황(근거) 판정
1 실행환경 활용 — 라이브러리 변경금지, 필수 4종(ptl.mvc·fdl.cmmn·psl.dataaccess·fdl.logging) 동일버전, 전이 Spring/Boot 버전 변경 금지 root pom.xml이 org.egovframe.boot:egovframe-boot-starter-parent:5.0.0 상속, core/cms-egov5-starter/pom.xml에 RTE 4종 + fdl-idgnr/fdl-property/fdl-filehandling + egovframe-boot-starter-security 선언. Maven Enforcer가 org.egovframe.rte:*:(,5.0.0)·egovframework.rte:*:(,5.0.0) 구버전 유입 차단. RTE는 maven 원본 그대로(포크·수정 없음). 충족
2 실행환경 설정 — 트랜잭션(AOP/annotation) + DB 커넥션풀. Java Config / Spring Boot Config 허용 @Transactional(annotation) 전 서비스 사용. 커넥션풀 = HikariCP(Boot 기본). Boot Configuration 방식으로 eGov service base·datasource·mapper scan 적용. 충족
3 MVC — @Controller/@RestController 핸들러매핑, Controller의 DAO/Mapper 직접호출 금지, 서비스 인터페이스 경유 전 컨트롤러 @RestController + Spring MVC. ArchUnit이 Controller→Mapper 직접의존 금지를 강제(Cms*ArchitectureTest). 충족
4 서비스 — EgovAbstractServiceImpl 확장(직접/간접) + 서비스별 인터페이스 구현 kr.cmsmsa.v2.egov5.CmsEgovServiceSupport extends EgovAbstractServiceImpl을 간접 확장하는 production @Service impl 다수. ArchUnit이 beAssignableTo(CmsEgovServiceSupport) 강제. 충족(모범적)
5 데이터액세스 — MyBatis Mapper Interface 적용 시 표준프레임워크 제공 MapperConfigurer + mapper annotation 사용, SqlSessionDaoSupport 직접호출 금지(가이드상 예외 없음) DAO 보유 9개 서비스의 mapper 인터페이스가 표준프레임워크 제공 @EgovMapper(org.egovframe.rte.psl.dataaccess.mapper.EgovMapper)를 부착(26개 인터페이스). mapper 등록은 각 *MyBatisConfiguration.java에서 표준프레임워크 제공 org.egovframe.rte.psl.dataaccess.mapper.MapperConfigurer로 @EgovMapper 인터페이스를 스캔·등록(mapper XML classpath*:mapper/**/*Mapper.xml). ArchUnit이 ① *Mapper의 @EgovMapper 부착, ② *MyBatisConfiguration의 MapperConfigurer 의존, ③ 수동 MapperFactoryBean 사용 금지를 강제. SqlSessionDaoSupport 직접호출 없음. 충족
6 실행환경 확장 — RTE 확장물은 org.egovframe.rte 패키지 밖, 클래스명 "Egov" 시작 금지 CmsEgovServiceSupport는 패키지 kr.cmsmsa.v2.egov5, 클래스명 "Cms…". ArchUnit이 RTE 파생 클래스의 "Egov" 명명 금지를 강제(규칙 6 테스트). 충족
7 전체 적용 — 최소 1개 이상의 Controller/Service/DAO 구성, 전 모듈 동일 RTE 버전·동일 아키텍처 규칙·동일 명명규칙. 모듈 예외는 사유 명시 시 허용 구현된 platform 10개 서비스(identity/site/navigation/content/board/media/code/audit/member + admin-bff)가 동일 ArchUnit 규칙 적용. admin-bff는 DAO 없는 BFF라 규칙 4/5 예외(아래 3절). 빈 골격(display/search)은 리액터에서 제외. 충족(예외 명문화)

권장 log4j-slf4j2-impl exclusion 근거 명시 fdl-logging이 log4j2 기반 log4j-slf4j2-impl을 가져오나, 본 프로젝트는 Logback 단일 SLF4J 바인딩을 유지하기 위해 해당 구현만 제외한다. 이는 Spring/Boot 버전 변경이 아니라 로깅 구현 교체이며, 규칙 1의 "전이 버전 변경 금지"에 위배되지 않음을 심사 근거로 명시한다.

eGovFramework 호환성확인 신청 범위 (Scope Lock)

기준일: 2026-06-16

이 문서는 누리지음의 호환성확인 레벨 2 제출 범위를 고정한다. 포함 모듈만 증빙 대상으로 삼고, 빈 골격·레거시 호환·migration fixture는 제출 범위 밖으로 격리한다.

신청 목적

  • eGovFramework 5.0 기반 MVC-Service-DataAccess 구조 확인
  • EgovAbstractServiceImpl 간접 확장 확인(CmsEgovServiceSupport)
  • mapper 인터페이스의 @EgovMapper(표준프레임워크 제공 mapper annotation) 적용 확인
  • Boot Java Config 기반 실행환경 설정 확인
  • controller/service/mapper 경계와 통합/smoke 검증 재현성 확인

신청 시 설명 문구(권장)

누리지음은 eGovFramework 5.0 기반의 범용 공공기관 CMS 플랫폼이며, 신청 범위는 구현 완료된 platform 10개 서비스(identity·site·navigation·content·board·media·code·audit·member·admin-bff)와 이를 받치는 core 모듈 전체다. admin-bff는 DAO 없는 BFF라 데이터액세스 규칙의 모듈 예외로 처리하며, display·search는 미구현 빈 골격이라 리액터에서 제외했다. 레거시 .do//ham/**//prog/**와 migration fixture는 선택형 호환 toolkit으로 분리해 범위 밖에 둔다.

제출 전 확인

  1. 신청 범위에 포함된 모듈만 증빙한다.
  2. 빈 골격·제외 모듈의 미구현 항목을 신청 범위와 혼동하지 않는다.
  3. 비밀값·raw row·세션/토큰·운영 접속정보는 증빙에서 제거한다.
